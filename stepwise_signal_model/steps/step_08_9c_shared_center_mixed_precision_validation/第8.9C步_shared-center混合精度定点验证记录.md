# 第8.9C步 shared-center混合精度定点验证记录

## 1. 本轮目的

本轮验证 shared-center 默认主线在 mixed precision 数值表示下是否能解决第 8.9 / 8.9B 暴露的量化敏感性问题。验证范围仍限定为：

single coarse peak / unresolved local cluster -> shared-center -> 65列工作子阵 -> 第 8.7 lazy cascade。

本轮不改第 8.7 算法、不改第 8.8 前端、不改 dispatch 阈值、不改 CFAR、不做 dual-center、不做 FPGA HDL、不做完整 bit-true fixed-point pipeline、不做定点 EVD、不做 MC=100。

## 2. 为什么统一定点失败后仍做 mixed precision

第 8.9 的统一 int16 / int18 / int24 结果保持 success 和安全性，但 route / confidence agreement 不达标，最大 az diff 仍较大。第 8.9B 进一步显示主要敏感源是 steering / template / cache 系数量化，Y_work int16 相对更稳。

因此，本轮不采用“所有数据统一升位宽”的思路，而是验证：

- Y_work 使用较低位宽，如 int16；
- steering / template / cache 使用较高位宽，如 int24；
- rank1 / 2D MUSIC / pair-local / refocus 等敏感 route 做 route-specific 高精度；
- float32 相关模式只作为数值上界或诊断参考，不作为 FPGA fixed-point 候选。

## 3. 本轮不是完整 FPGA bit-true

本轮是 mixed precision numerical influence validation，不等价于完整 FPGA bit-true 实现：

- 不验证硬件流水线；
- 不验证定点 EVD；
- 不验证 FFT / CFAR bit-true；
- 不验证 BRAM / DDR 调度；
- 不验证 HDL。

EVD、矩阵乘法和第 8.7 route 逻辑仍在 MATLAB double 中执行；本轮只在进入计算前对 Y_work 和 coefficient/cache 做量化再反量化。

## 7. 量化模型

复数数据 z = x + j y 分别量化实部和虚部。单位幅值 steering / template / cache 使用饱和均匀量化：

Q_B(x) = clip(round(x * S), -Imax, Imax) / S

其中 Imax = 2^(B-1)-1，S = Imax。

Y_work 使用 block floating scale：

scale_y = max(abs(real(Y_work(:))), abs(imag(Y_work(:))), eps)

先计算 Y_norm = Y_work / scale_y，再量化 Y_norm，最后反缩放得到 Y_q。

## 9. 关键观察

y16_coeff24_all 是本轮 fixed-point 候选中 overall output_equivalent 最好的模式：

- output_equivalent = 0.928030；
- core_scenario_output_equivalent = 0.911111；
- medium_or_above_output_equivalent = 0.943907；
- route_agreement = 0.950758；
- confidence_agreement = 0.950758；
- p95 az diff = 0.04 deg；
- max core az diff = 0.76 deg；
- false-high = 0；
- boundary-missed = 0。

route-specific 模式没有闭合。y16_rank1_2d_coeff24_rest16 的 output_equivalent = 0.926515，core_scenario_output_equivalent = 0.909722，max core az diff = 0.94 deg，仍不满足闭合标准。

float32_all 作为诊断参考接近闭合，但它不是 fixed-point 候选，不能据此进入 FPGA kernel design。

## 10. worst cases

worst_cases.csv 为每个 mixed mode 保留 az diff 最大的前 50 个 in-scope 样本。最大差异主要来自 close_coherent_pair 中的 boundary-route flip，例如 trial_id=95、SNR=16、mc=5，double route 为 boundary_unreliable，量化后可翻转为 common_el_refocus_power_rank1 或 level2_rank1_fallback，az_diff 达到 0.94 deg。

这说明本轮问题仍不是 safety 崩溃，而是边界 route / candidate tie / flat objective 对系数量化敏感。

## 11. storage estimate

storage estimate 按 coefficient/template 类别估算，包括 level2 music、level2 rank1、refocus、2D MUSIC、pair-local。该估算不代表最终 FPGA 资源映射。

本轮 best overall candidate y16_coeff24_all 的估算存储为 7.115421 MB；best storage-efficient candidate y16_rank1_coeff24_rest16 为 4.904633 MB，但未通过输出等价标准。

## 12. 推荐结论

- mixed_precision_pass_flag = 0；
- recommended_fixed_point_architecture = not_recommended_until_mixed_precision_closes；
- proceed_to_fpga_kernel_design_flag = 0；
- proceed_to_mc100_flag = 0；
- blocker_if_any = mixed_precision_not_closed；
- next_step_recommendation = add margin-aware confidence / candidate tie guard or raise route-specific coefficient precision。

本轮 mixed precision 没有闭合。虽然 false-high 和 boundary-missed 继续保持为 0，且 p95 az diff 已可压到 0.04 deg，但 output_equivalent、core_scenario_output_equivalent 和 max core az diff 不满足进入 FPGA kernel design 的标准。

下一步应优先做 margin-aware confidence / candidate tie guard / boundary failure_reason calibration，必要时再验证更高精度或更细分类的 coefficient cache 表示。
