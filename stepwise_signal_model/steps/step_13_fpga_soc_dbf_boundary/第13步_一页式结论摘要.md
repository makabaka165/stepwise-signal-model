# 第13步 一页式结论摘要

## Step13结论

Step13定位为 FPGA/SoC 协同边界收束与 FPGA DBF 硬件实现方案。核心边界是：

```text
FPGA: Z = W^H Y
CPU/SoC: Rz / G_cache / 2D ML / topK / C05 / confidence / fallback
```

Step13不改变 Step11.7 backend 默认行为。

## FPGA做什么

FPGA负责：

- DBF权值 `W` 存储/读取
- 阵元域或局部工作子阵输入 `Y` 的流式接收
- 复乘加流水线
- `Z = W^H Y`
- fixed-point scale / rounding / saturation
- `Z` 输出接口和量化元数据

## CPU/SoC做什么

CPU/SoC负责：

- 接收 `Z`
- 构造或读取 `Rz = Z Z^H`
- 管理 `G_cache`
- 执行 beamspace ML 2D候选搜索
- 执行 score ranking / topK
- 执行 C05 policy
- 执行 confidence / boundary / fallback
- 负责日志、调试、策略控制和最终输出

## Step12保留价值

Step12保留为未来 ML score-core accelerator 的定点和ranking敏感性支撑材料。`mixed_Z16_G24_Rz24` 不作为 Step13 DBF W/Y/Z 默认推荐格式。

## 推荐位宽候选

Step13 DBF 初始候选：

- `mixed_W18_Y16_Z24`
- `mixed_W24_Y16_Z24`

Step13 DBF pass只说明 FPGA DBF 可行，不说明完整 ML backend FPGA 化。

## 是否进入RTL DBF prototype

若 quick/smoke 显示上述两个候选格式满足 Z误差、beam power误差、top beam保持和clip约束，建议下一步进入 RTL DBF prototype。建议从 `beam_parallel_B_lanes` 架构开始。

## 禁止扩大边界

本步骤禁止把以下内容描述成已经完成：

- 完整 FPGA backend
- 完整二维 ML 搜索硬件化
- Step11.7 full backend RTL
- ML score-core RTL 主线
- C05 policy / confidence / fallback / boundary 完整硬化

quick/smoke不是formal closure，不应作为formal结论写入。
