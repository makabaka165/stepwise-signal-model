# Step13 DBF RTL Testbenches

Testbenches:

- `tb_dbf_complex_mac.v`: standalone hand-written checks for `conj(W) * Y`.
- `tb_dbf_core_accum.v`: compact golden-vector smoke for the raw DBF
  accumulator.
- `tb_dbf_z24_quantizer.v`: hand-written positive, negative, rounding, and
  saturation checks for the signed Z24 quantizer.
- `tb_dbf_core_z24.v`: compact golden-vector smoke for raw accumulator plus
  Z24 shift/round/saturate output.

The accumulator testbench includes:

```text
../results_step13_fpga_soc_dbf_boundary/rtl_golden/step13_dbf_rtl_golden_vectors.vh
```

Run the current Vivado XSim smoke from the Step13 directory:

```powershell
powershell -ExecutionPolicy Bypass -File sim/run_xsim_dbf_smoke.ps1
```

The older Icarus smoke entry point remains available when `iverilog` and
`vvp` are installed:

```bash
bash sim/run_iverilog_dbf_smoke.sh
```

The smoke writes a small CSV to:

```text
results_step13_fpga_soc_dbf_boundary/rtl_sim/dbf_core_accum_output.csv
results_step13_fpga_soc_dbf_boundary/rtl_sim/dbf_core_z24_output.csv
```

No waveform file is generated by default.

The Z24 datapath remains FPGA DBF only:

```text
ACC raw accumulator -> shift -> round -> saturate -> signed int24 Z output
```

It does not implement `Rz`, `G_cache`, 2D ML search, topK, C05, confidence,
boundary, fallback, or a complete FPGA backend. Those remain CPU/SoC
responsibilities by design.
