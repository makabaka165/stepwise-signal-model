## 一、第 8.5 步背景与目标

### 1.1 与第 8 步的关系

第 8 步（`steps/step_08_routeB_innovation/`）已完成 proto1~9 的算法仿真，全部跑在抽象 64 元 ULA 上（载频 2.7 GHz, d=0.047m）。第 8 步已**冻结**，proto6 (FBSS + Root-MUSIC) 是最终保留的主创新点。

第 8.5 步（本目录 `steps/step_08_5_routeB_array/`）的目的是**把第 8 步算法套用到本项目真实的 192×32 圆柱阵上**，解决"算法在 ULA 上验证、雷达却是圆柱阵"的脱钩硬伤。

**严格分工**：

- 第 8 步：抽象 ULA、算法验证、已冻结，只通过 `addpath` 引用其函数
- 第 8.5 步：圆柱阵工程仿真、增量迭代、所有新代码与结果都在本目录

### 1.2 当前阶段的核心问题（来自 proto10 v2 的发现）

proto10 v1/v2 跑完后暴露了一个关键事实：

> **proto10 只用了 192×32 圆柱阵的 32 列 × 1 层 = 32 个阵元**，等于浪费了剩下 31 层的相干能量。当目标 az 已经由上游 Step 5 检出后，所有 32 层在该方位上都应当贡献 SNR，但 proto10 把它们扔掉了。

退化率排序也印证了这一点：

| 路线 | 平均单元退化率 | 关键差异 |
|---|---:|---|
| `cylindrical_grid_music_baseline` | 63.74% | N=32 列 + 圆柱弧段几何（1 层） |
| `cylindrical_root_music_proto10` | 56.39% | N=32 列 + 圆柱弧段几何（1 层） |
| `pure_ula_root_music_reference` | 15.83% | N=32 列 + 直 ULA（1 层） |
| `pure_ula_root_music_64ch_proto6_replay` | 0.00% | N=64 列 + 直 ULA（1 层） |

两个独立恶化因素：
1. 阵元数 N=32 → N=64：退化率 15.83% → 0%
2. 直 ULA → 圆柱弧段 ULA 近似：退化率 15.83% → 56.39%

**proto14 的存在意义**：在不增大方位孔径（保持 N_arc=32 或扩大到 48）的前提下，用满 32 层换取 ~15 dB 的 SNR 增益，相当于把 SNR 曲线整体左移 15 dB。这能否把"完全同相小间隔退化"压下去，是 proto14 要回答的核心问题。

### 1.3 当前阶段的论文目标

- **正面结果**（如 proto14 救活）：圆柱阵 + Route B + 32 层俯仰相干合成 + Root-MUSIC，可以在工程参数下复现 proto6 优势 → 写成"圆柱阵适配方案"主章节
- **负面结果**（如 proto14 仍不行）：在完全同相小间隔双目标场景下，单纯增大阵元数仍救不活 → 失败边界更明确，论文写成"边界刻画"

无论哪种结果，proto14 都比 proto10 v2 的"只用 1 层"更接近你的真实雷达系统，论文价值都更高。

## 二、圆柱阵关键几何参数

来自 `core/config/sim_cfg.m`，**不要在 proto14 脚本里重新设定**：

```matlab
cfg.arr.Naz    = 192;          % 圆周列数
cfg.arr.Nel    = 32;           % 高度层数
cfg.arr.R      = 0.4;          % 圆柱半径 (m)
cfg.arr.dz     = 17e-3;        % 层间高度 (m)
cfg.arr.dPhi   = 360/192;      % = 1.875 deg
cfg.arr.fc     = 10e9;         % 载频
cfg.arr.lambda = 0.030;        % 波长
cfg.beam.sectorHalf = 60;
cfg.beam.subNaz     = 65;      % = 2*floor(60/1.875)+1，工作子阵列数
```

派生量（在脚本中算出来并打印到日志）：

```text
arc_dist          = 2*pi*R/Naz       = 0.01309 m
arc_dist / lambda                    = 0.4363       (< 0.5，方位无欠采样)
dz / lambda       = 17e-3 / 0.030    = 0.5667       (略大于 0.5，俯仰临界但可用)
subArc_span_deg   = 64 * 1.875       = 120 deg      (工作扇区跨度)
elev_aperture     = (Nel-1) * dz     = 0.527 m      (俯仰总孔径)
elev_aperture/lambda                 = 17.567        (俯仰电尺寸)
```

**关键观察**：
- 方位 65 列 × 32 层 = **2080 阵元** 是雷达每个 CPI 的实际工作子阵
- 方位由于曲率失配只能取中心 N_arc 列做 ULA 近似（推荐 N_arc=32，或扩大到 48）
- 俯仰 32 层 dz/λ=0.5667 在 el=0 时不出栅瓣（sin(el) 在 ±arcsin(λ/(2*dz))=±27.8°内安全）
- 32 层相干合成增益上限 = 10·log10(32) ≈ **15.05 dB**

**两级嵌套子阵选择**：

```
全阵 192 列 × 32 层
    │【一级】arr_cyl(cfg, azCtr_deg) 按 sectorHalf=60° 选 65 列
    ▼
工作子阵 65 列 × 32 层 (2080 阵元，跨方位 120°)
    │【二级】proto14 在本级动手
    │   方位：取中心 N_arc 列做 ULA 近似 (推荐 32)
    │   俯仰：用满 32 层做相干合成
    ▼
proto14 输入 = N_arc 列 × Nel 层 = N_arc * Nel 阵元
```

### 4.2 核心信号模型（保真信号 + 俯仰相干合成 + ULA Root-MUSIC）

**逻辑 A：信号生成必须用真实圆柱阵 3D 坐标**

```matlab
% 1) 工作子阵 (65 列 × 32 层)
arrInfo = arr_cyl(cfg, azCtr_deg);            % azCtr_deg=0

% 2) 选取方位 N_arc 列 × 全部 32 层
iel_select_all = 1:cfg.arr.Nel;               % 32 层全用
col_mid = round((cfg.beam.subNaz + 1) / 2);   % = 33
N_arc = 32;
col_select = (col_mid - N_arc/2 + 1):(col_mid + N_arc/2);

% 3) 三维坐标 (N_arc x Nel x 3)
X3d = arrInfo.XAct(col_select, iel_select_all);   % N_arc x Nel
Y3d = arrInfo.YAct(col_select, iel_select_all);
Z3d = arrInfo.ZAct(col_select, iel_select_all);

% 4) 视轴方向相位归一化（与 proto10 v2 一致，扣除圆柱阵固定几何相位）
unit_ref = [cosd(0) * cosd(azCtr_deg), cosd(0) * sind(azCtr_deg), 0];
A_ref_2d = exp(-j * 2*pi / lambda * (X3d * unit_ref(1) + Y3d * unit_ref(2)));

% 5) 用真实坐标生成 2D steering（每个目标都对应 N_arc x Nel 的复振幅矩阵）
unit_a = [cosd(el_a) * cosd(theta_a), cosd(el_a) * sind(theta_a), sind(el_a)];
A_a_2d = exp(-j * 2*pi / lambda * (X3d * unit_a(1) + Y3d * unit_a(2) + Z3d * unit_a(3)));
% A_a_2d 维度: N_arc x Nel

% 6) 生成 2D 观测 (N_arc x Nel x T_snap)
y_2d = zeros(N_arc, cfg.arr.Nel, T_snap);
for ie = 1:cfg.arr.Nel
    A_a_col = A_a_2d(:, ie);              % N_arc x 1
    A_b_col = A_b_2d(:, ie);
    y_clean_col = (conj(A_ref_2d(:, ie))) .* (A_a_col * s1 + A_b_col * s2);
    noise_col = sqrt(noise_power/2) * (randn(N_arc, T_snap) + j * randn(N_arc, T_snap));
    y_2d(:, ie, :) = y_clean_col + noise_col;
end
```

**逻辑 B：俯仰相干合成（用 el_assumed 把 32 层折叠成 1 层）**

```matlab
% el_assumed 来自 Step 5 检测（论文里要写"已知"），脚本里用真值或固定假设
el_assumed = el_a;                            % 推荐与 el_a/el_b 一致 (同俯仰双目标)

% 对每一列 n 单独算 32 层的俯仰 steering，沿 z 求和后归一化
y_combined = zeros(N_arc, T_snap);            % N_arc x T_snap
for n = 1:N_arc
    z_col_n = Z3d(n, :).';                    % Nel x 1（这一列 32 层的 z）
    % el_assumed 方向 z 分量
    steer_el_n = exp(-j * 2*pi / lambda * z_col_n * sind(el_assumed));
    % 还有 x,y 分量？因为列号 n 的 x,y 在 32 层间相同（圆柱阵每列共面），
    % 所以 x,y 分量不影响层间相位差，只看 z。下面这步把 32 层向 el_assumed 对齐求和
    y_col_n = squeeze(y_2d(n, :, :));         % Nel x T_snap
    y_combined(n, :) = (1/sqrt(cfg.arr.Nel)) * (steer_el_n' * y_col_n);
end
```

**逻辑 C：方位 DOA 估计（与 proto10 完全一致）**

```matlab
d_eq = 2*pi*cfg.arr.R / cfg.arr.Naz;          % ~0.01309 m
K_fbss = 28;                                   % FBSS 子阵长度
[doa_est, dbg] = doa_root_music_array(y_combined, K_fbss, lambda, d_eq, 2);
```

**为什么这样设计**：

1. **物理对应**：上游 Step 5 已经做了 2D 检测，知道目标俯仰；DOA 阶段拿到 el_assumed 作为先验，把 32 层折叠成 1 列输入
2. **SNR 增益**：32 层相干合成理论 +15.05 dB；如果 el_assumed = 真实 el，几乎无损
3. **el 失配代价**：每偏 1°，相干损失 ~10·log10(|sinc(π·dz·Δel/λ·Nel)|²) （论文里要量化）
4. **算法接口零改动**：仍用 doa_root_music_array.m，DOA 阶段不知道圆柱阵的存在

### 4.8.1 触发与目标

proto14b 的诊断结果（来自 summary.csv）：

|---:|---|---:|---:|---:|---|

**关键诊断**：所有 200 样本 degraded=0（算法没崩）；mean_bias 极小（系统偏差 < 0.03°）；但 RMSE ≈ 0.13° **超过** tol_abs=0.1° → 失败是**估计抖动**而非算法错误。扩 N_arc 反而让 RMSE 上升 → **Root-MUSIC 的 Vandermonde 假设在弧段子阵上不严格，引入子空间向量偏差，对小间隔分辨致命**。

### 4.8.2 设计思路（最小改动）

| 部分 | proto14 / 14b | proto15.A |
|---|---|---|
| 工作子阵选取 | 65 列 × 32 层 → N_arc=32 中心列 × 32 层 | **保持不变** |
| 俯仰相干合成 | 32 层 → 1 层 (y_combined, +15 dB 增益) | **保持不变** |
| 视轴相位归一化 | conj(A_ref) | **保持不变** |
| 协方差 + FBSS | Rxx = y_combined·y_combined'/T, Rfb = FBSS | **保持不变**（K_fbss=28） |
| 子空间分解 | eig(Rfb), 噪声子空间 En | **保持不变** |
| **DOA 估计** | **Root-MUSIC（用 d_eq Vandermonde 假设求根）** | **grid-MUSIC（用真实弧段 X/Y 坐标做谱搜索）** |

**新增的核心代码块**（在主脚本里写，不新建函数）：

```matlab
% ===== proto15.A 核心：真实弧段流形 grid-MUSIC =====
% 子阵 FBSS 后的有效"等效中心子阵" K_fbss 列
% FBSS 等效坐标取中心 P=N_arc-K_fbss+1 个子阵的"中央"那个子阵
P_sub = N_arc - K_fbss + 1;   % FBSS 子阵数
p_mid = round((P_sub + 1) / 2);  % 中央子阵的起始列
col_center = col_select(p_mid : p_mid + K_fbss - 1);   % 等效中心子阵的全局列号
X_K = arrInfo.XAct(col_center, iel_select);  % K_fbss × 1
Y_K = arrInfo.YAct(col_center, iel_select);
% 视轴归一化用的参考相位（与 proto14 一致，只是子阵维度从 N_arc 缩到 K_fbss）
A_ref_K = exp(-j * 2*pi / lambda * (X_K * cos(deg2rad(azCtr_deg)) + Y_K * sin(deg2rad(azCtr_deg))));

% 子空间分解（与 proto14 一致）
[V, D] = eig(Rfb);
[~, idx] = sort(real(diag(D)), 'descend');
V = V(:, idx);
En = V(:, Lc+1:end);

% grid-MUSIC 谱搜索
search_range = bw_eq;   % 在中心 ±bw_eq 范围搜，覆盖 sep_factor=1 的最大间隔
search_step  = 0.005;   % 0.005° 步长，约 bw_eq/1000 精度
angle_grid   = (azCtr_deg - search_range):search_step:(azCtr_deg + search_range);
Pmu = zeros(1, numel(angle_grid));
for ii = 1:numel(angle_grid)
    az_test = angle_grid(ii);
    % 真实圆柱阵流形（视轴归一化版）
    a_test = exp(-j * 2*pi / lambda * (X_K * cosd(az_test) + Y_K * sind(az_test)));
    a_test = a_test .* conj(A_ref_K);   % 与 y_combined 的归一化对齐
    a_test = a_test / norm(a_test);     % 单位化
    den = real(a_test' * (En * En') * a_test);
    Pmu(ii) = 1 / max(den, eps);
end

% 峰值检测（找两个最强局部峰）
[~, peak_inds] = FindLocalPeak_NoEdge_Fun(Pmu);
if numel(peak_inds) < Lc
    doa_est = nan(1, Lc);
else
    doa_est = sort(angle_grid(peak_inds(1:Lc)));
end
```

   ```matlab
   col_center = col_select(p_mid : p_mid + K_fbss - 1);   % 取 col_select 的 [3..30] 列
   X_K = arrInfo.XAct(col_center, iel_select);
   Y_K = arrInfo.YAct(col_center, iel_select);
   ```
   断言：`numel(col_center) == K_fbss && col_center(end) - col_center(1) == K_fbss - 1`

2. **视轴归一化 A_ref_K**：用 `X_K, Y_K` 重算（**不要**复用 N_arc 维度的 A_ref），保证与 FBSS 后的协方差维度对齐：
   ```matlab
   A_ref_K = exp(-j * 2*pi / lambda * (X_K * cosd(azCtr_deg) + Y_K * sind(azCtr_deg)));
   ```

3. **路线 2 流形**（真实弧段）：
   ```matlab
   a_real(ii) = exp(-j * 2*pi / lambda * (X_K * cosd(az_test) + Y_K * sind(az_test)));
   a_real(ii) = a_real(ii) .* conj(A_ref_K);
   ```

4. **路线 3 流形**（ULA Vandermonde，用于消融）：
   ```matlab
   d_eq = 2*pi * cfg.arr.R / cfg.arr.Naz;
   a_ula(ii) = exp(-j * 2*pi * d_eq * (0:K_fbss-1).' * sind(az_test) / lambda);
   % 注意：路线 3 不点除 A_ref_K，因为 ULA 流形本身就是 azCtr 相对的
   ```

5. **谱归一化**：每个 a_test 单位化后再算分母，避免 |a|² 在不同 az 下变化造成谱形失真：
   ```matlab
   a_test = a_test / norm(a_test);
   den = real(a_test' * (En * En') * a_test);
   Pmu(ii) = 1 / max(den, eps);
   ```

6. **峰值检测**：用 `FindLocalPeak_NoEdge_Fun`，返回的 peak_inds 按谱值从大到小排序，取前 2 个：

   ```matlab
   [~, peak_inds] = FindLocalPeak_NoEdge_Fun(Pmu);
   if numel(peak_inds) >= Lc
   ```

### 4.9.2 背景与假设（数学推导）

完全同相相干源：`s1(t) = s2(t) = s(t)`，源协方差秩 1：

```
Ps = E[s s^H] = |s|² · [1 1; 1 1] = |s|² · v v^H,  v = [1; 1]
```

FBSS 把秩 1 协方差恢复到秩 ≤ 2，关键在 P 个子阵之间的相位累积。对 ULA：

```
Ps_eff[1,2] = |s|² · (1/P) · Σ_{p=0}^{P-1} exp(j 2π d (sin θ_1 - sin θ_2) p / λ)
```

这是几何级数。当 (P-1)·d·sin(Δθ/2)/λ 很小时，级数接近 1，**Ps_eff 仍接近秩 1**，FBSS 没有恢复出严格秩 2。

**proto6 vs proto14 对比**：

| 量 | proto6 64元 ULA | proto14 32元等效 |
|---|---:|---:|
| N | 64 | 32 |
| K_fbss | 56 | 28 |
| **P_sub = N-K+1** | **9** | **5** |
| K / N | 0.875 | 0.875 |
| sep=10 theta_sep | 0.28° | 0.55° |
| (P-1)·d·sin(θ_sep/2)/λ | 8 × 0.42 × 0.00244 ≈ 0.0082 周期 | 4 × 0.44 × 0.00472 ≈ 0.0083 周期 |
| 全孔径相位差 (N-1)·d·sin(θ_sep/2)/λ | 0.065 周期 | 0.064 周期 |
| sep=10 SNR90 | 20 dB ✓ | NaN ✗ |

**关键观察**：两者的"全孔径相位差"几乎相同（0.064~0.065 周期），意味着物理分辨能力相当。差异在 **P_sub（9 vs 5）**。

**假设 H**：proto14 sep=10 失败的主因是 P_sub=5 不够，**与流形选择、算法机制无关**。

**判据**：若 K_fbss=24 (P_sub=9) 时 sep=10 救活（SNR90 ≤ 24 dB），证明假设成立。

## 四点十、验证型实验 B：源相干度敏感性扫描

### 4.10.1 任务定位

**性质**：**验证型实验**，不是新 Prototype。命名带 `verify_` 前缀，**不挂 Prototype 编号**。

**目的**：proto10/14/14b/15.A 的所有失败都基于"完全同相相干源" `s1 ≡ s2` 这个最严苛 worst-case。实际雷达双目标相干场景（多径同源反射、临近编队目标等）由于路径几何差异，几乎不可能出现严格 0° 相位差。**本实验扫描 s2 相位偏置 Δφ ∈ {0°, 5°, 15°, 30°, 60°, 90°, 180°}**，量化"完全同相 worst-case" vs "工程实际准相干场景"的成功率差距。

**论文价值**：
- 如 Δφ ≥ 30° 时 sep=10 工作：**重新框定 proto14 失败为"工程上无意义的数学极限"**，论文主结论从"失败"翻转为"成立 + 准相干边界"
- 如 Δφ 全程都不工作：sep=10 失败与相干度无关，是其他问题（需上 proto15.B / PME）
- 不论结果如何，**相干度敏感性曲线本身**就是论文里有价值的图

### 4.10.2 背景与假设

**完全同相相干源的物理稀缺性**：

| 场景 | 相位差来源 | 典型 Δφ 分布 |
|---|---|---|
| 多径同源反射（同一物体的散射点） | 路径长度差 ΔR | Δφ = 2π·2·ΔR/λ；λ=3cm 时 ΔR=2.5mm 即 Δφ=60° |
| 临近双目标（编队飞机） | 各自独立散射 | Δφ 随机分布 [0, 2π) |
| 完全同相 `s1 ≡ s2` | **数学极端** | **Δφ ≡ 0°（实测几乎不出现）** |

**假设 K**：proto14 框架在 Δφ ≥ 30° 时 sep=10 工作；完全同相 sep=10 失败是"数学极限"，对工程意义不大。

**判据**：若某个 Δφ ∈ {30°, 60°, 90°} 在 sep=10 SNR ≤ 24 dB 时 tol_rate ≥ 0.85，假设 K 成立。

### 4.10.3 设计：最小改动

## 四点十一、验证型实验 C：K_fbss × Δφ 联合扫描（防御审稿）

### 4.11.1 任务定位

**性质**：**验证型实验**，不是新 Prototype。命名带 `verify_` 前缀，**不挂 Prototype 编号**。

**目的**：A 实验单独证明 P_sub 改善 sep=10（NaN → 30 dB）；B 实验单独证明 Δφ 改善 sep=10（Δφ=15° → 16 dB）。但**审稿人几乎必然会问**：

> "P_sub 和 Δφ 是各自独立的改进机制？还是冗余的（都解决 FBSS 去相关）？还是协同的（联合更优）？"

**A 和 B 都没回答这个问题**。本实验在 proto14 主脚本上联合扫描 **K_fbss × Δφ 笛卡尔积**，给出三类联合效应的定量判定。

**论文价值**：
- 防御审稿，论文 X.6 节"工程门槛"可以严谨写出"K=24 vs K=28 在 Δφ ≥ 15° 时是否冗余"
- 给出工程实现建议：worst-case Δφ=0° 用 K=24；工程典型 Δφ ≥ 15° 用 K=28（如冗余成立）

### 4.11.2 背景与假设（物理直觉）

| 假设 | 含义 |
|---|---|
| **假设 J1 (冗余假设)** | K=24 和 Δφ ≥ 15° 解决同一问题（FBSS 去相关）。预期：K=24 + Δφ=15° ≈ K=28 + Δφ=15°（联合不比单独 Δφ 好） |
| 假设 J2 (加性假设) | K=24 和 Δφ 各自降低 SNR 门槛 N1, N2 dB。预期：联合降低 ≈ N1 + N2 dB |
| 假设 J3 (协同假设) | 联合降低 > N1 + N2 dB |
| 假设 J4 (冲突假设) | K=24 在高 Δφ 时反而恶化（不太可能但要排除） |

**物理直觉支持 J1（冗余）**：FBSS 把秩 1 协方差 `Ps = |s|² · v v^H` 恢复到秩 ≥ 2 的去相关能力，依赖子阵间相位累积；当源本身去相干 (Δφ ≥ 15° 让 `|Ps[1,2]|/Ps[1,1] < 0.97`) 时，FBSS 几乎不需要工作。所以 K=24 vs K=28 在 Δφ ≥ 15° 时差异应当很小。

但**这是物理直觉，必须实验验证**。审稿人不接受"直觉"。

### 4.11.3 设计：双层笛卡尔积扫描

> "P_sub 和 Δφ 在小间隔上呈**协同**效应：联合采用 K_fbss=24 + Δφ ≥ 15° 比单一改进降低额外 X dB SNR 门槛。物理解释：FBSS 平均提供阵列域去相关，源相位差提供信号域去相关；二者作用于协方差矩阵的不同分量，独立累积。"

无论 J1/J3 哪个成立，论文 X.6 节都有具体定量结论。
