# 第8.11步 探索路线取舍与论文定位

## 1. 取舍总表

| 路线 | 结论 | 最终定位 |
|---|---|---|
| dual-center | 舍弃默认主线 | 未来多粗峰工程前端 |
| complex-gain / V2 | 不作为主线 | 未来一般相干源扩展 |
| weak target 求解 | 不作为主线 | 边界保护 / 未来弱目标增强 |
| near anti-phase 求解 | 不作为主线 | 边界保护 / 未来反相模型 |
| 第 8.10 unified model selection | 不替代 cascade | 理论解释尝试 / 负结果 |
| 第 8.9 fixed-point hardening | 未闭合 | FPGA 定点边界分析 / 未来工作 |

## 2. 为什么不采用第 8.10

第 8.10 统一模型选择当前实现不安全：

- success 远低于 cascade；
- false-high 非零；
- boundary-missed 非零；
- H1/H2/H3 选择分布不符合物理预期；
- near anti-phase 容易被 H2 高置信吸收；
- large-el 没能稳定转入 H3。

因此第 8.10 不作为最终主算法。它的价值是反向论证：当前问题不是简单把所有模型放入统一残差评分即可解决，工程 cascade 的保守 route gate 仍有必要。

## 3. 第 8.9 如何定位

第 8.9 不是失败的无用结果，而是 FPGA / SoC 分工的重要边界证据：

- float32 基本可用，说明算法数值上不是完全不可移植；
- Y_work int16 相对稳定；
- steering/template/cache 系数量化更敏感；
- refocus-rank1 route flip 是后续硬件化的风险点；
- 当前不建议直接进入纯 FPGA 定点 kernel design。

## 4. 论文定位

建议论文主线写成：

**提出一种面向全息凝视圆柱阵局部未分辨目标簇的 shared-center 增强测角链路。**

不要写成：

- “提出普适相干源 MUSIC 改进算法”；
- “解决所有多目标相干源分辨问题”；
- “完成完整 FPGA 定点硬化实现”。

## 5. 三个创新点

1. 前端检测驱动的 shared-center 局部增强测角框架；
2. 动态 65 列工作子阵与局部 steering 模板复用；
3. 保守级联增强测角与边界保护机制。

## 6. 后续建议

下一步应进入论文撰写、答辩图整理和 final demo 讲解材料准备。算法层面不再继续扩大范围。
