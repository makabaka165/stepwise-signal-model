# 第8.11步 最终算法流程与公式说明

## 1. 输入与前端

前端链路为：

`LFM / 阵元级回波 -> 距离脉压 -> MTD -> CFAR -> 粗波束扫描 / 三波束比幅`

输出字段：

- `frontend_out.rangeIdx`
- `frontend_out.dopplerIdx`
- `frontend_out.coarseAz`
- `frontend_out.coarseEl`
- `frontend_out.frontend_state`

## 2. 前端状态判断

`frontend_state == single_peak_in_scope` 时进入 shared-center 主线。

`frontend_state == two_close_peaks_merge_candidate` 当前论文中标记为 merge candidate，不作为默认主线求解，可作为未来工作。

`frontend_state == two_separated_peaks_out_of_scope` 不进入 shared-center，交给上层多目标前端或未来工程分支。

`frontend_state == weak_secondary_candidate` 不高置信输出，保守处理。

## 3. shared-center 选阵

以 `coarseAz` 或局部中心吸附最近实际阵元列：

`selectedCenterColumn = argmin_k |wrap180(phiCol(k) - coarseAz)|`

中心列左右各 32 列，共 65 列：

`selectedWorkColumns = selectedCenterColumn + [-32,...,0,...,+32]`

记录：

- `selectedCenterColumn`
- `selectedCenterAz`
- `selectedWorkColumns`

## 4. Y_work 构造

从前端同一份观测数据构造：

`Y_work in C^(65 x 32 x T_snap)`

其中 `T_snap=Np=32`。默认：

`derotation_mode = none`

第 8.8B 已验证 `no_derotation / derotation_minus / derotation_plus` 的 route、confidence、success 和输出一致，因此 Doppler de-rotation 保留为可选工程字段，不强制默认启用。

## 5. 剪枝版 cascade

### Branch A：常规 MUSIC 可分辨

若 level2 / MUSIC 谱已经稳定给出双峰，且 peak separation、prominence、rank proxy 等置信指标可靠，则输出 MUSIC 结果。

### Branch B：强相干近邻 fallback

若 MUSIC 呈单峰或双峰合并，但观测符合 single coarse peak 内强相干近邻特征，则执行：

1. common-el refocus；
2. rank1 fallback；
3. candidate score / pair-sep / confidence 判断。

该分支是 close coherent pair 的主力。

### Branch C：二维分离分支

若二维信息显示俯仰差明显或层次二压缩不适用，则执行：

1. 2D MUSIC；
2. pair-local refinement；
3. 可靠性判断。

该分支是 large-el 场景主力。

### Branch D：边界保护

若观测不支持可靠输出，或多个 route 判据冲突，则输出：

- `low_confidence`
- `boundary_unreliable`

weak target、near anti-phase、two separated coarse peaks 均不作为当前默认主线可解问题。

## 6. 输出

最终输出包含：

- `route_used`
- `confidence_flag`
- `az_est`
- `el_est`
- `failure_reason`
- `low_confidence / boundary_unreliable` 标志

安全优先级高于 success：不得用高置信输出覆盖边界不可靠样本。
