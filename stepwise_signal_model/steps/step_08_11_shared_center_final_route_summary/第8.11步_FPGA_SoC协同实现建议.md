# 第8.11步 FPGA / SoC 协同实现建议

## 1. 总体结论

当前不建议承诺“完整第 8.7 算法全定点 FPGA 实现”。更稳妥的第一版工程路线是 FPGA + CPU/ARM/DSP/浮点 IP 协同。

原因：

- 第 8.9 系列表明 refocus-rank1 判据、steering/template/cache 系数量化对定点敏感；
- 第 8.9C mixed precision 未闭合；
- 第 8.9D / 8.9E 说明简单 guard、normalization、hysteresis 不能直接作为主线修复；
- 第 8.10 表明简单统一模型选择不能替代 cascade；
- 因此不应把所有 route selection 和 EVD / rank1 决策硬塞入纯 FPGA 定点流水。

## 2. FPGA 侧适合承担

1. LFM 脉压；
2. MTD / FFT；
3. CFAR；
4. coarse beamforming；
5. 65 列工作子阵抽取；
6. local steering template LUT；
7. refocus power 计算；
8. MUSIC / 2D 投影的并行加速；
9. 部分 rank1 candidate score 计算。

这些模块计算规整、并行度高、访存模式可预估，适合作为 FPGA 加速核。

## 3. CPU / ARM / DSP / 浮点 IP 侧适合承担

1. EVD / 子空间分解；
2. rank1 candidate 决策；
3. pair-local 最终决策；
4. confidence / boundary 状态机；
5. route selection；
6. 日志、调试指标和跟踪接口。

这些模块对数值稳定、边界判据和可解释性要求较高，第一版更适合保留在软件或浮点协处理侧。

## 4. 推荐工程拆分

推荐把硬件实现目标写成：

`FPGA完成前端高吞吐预处理与候选/谱计算加速，SoC侧完成EVD、route decision和边界保护。`

不建议写成：

`完整第8.7算法已经适合纯FPGA定点实现。`

## 5. 后续工作

若后续继续做硬件化，应先完成：

- bit-true 前端定点验证；
- steering/template/cache 分层量化策略；
- route-specific coefficient precision；
- EVD / rank1 fallback 的浮点或高精度 IP 调度；
- boundary / confidence 状态机的硬件可观测指标定义。
