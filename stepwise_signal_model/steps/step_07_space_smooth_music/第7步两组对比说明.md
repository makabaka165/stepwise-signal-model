# 第7步两组对比说明

## 1. 文档目的

本文档用于总结第 7 步中已经完成的两组核心对比，包括：

1. `旧路线 vs 新路线(完整T)`
2. `完整T vs 中心截取T vs 功率选波束T`

文档重点说明以下内容：

1. 每组对比各自的算法思路
2. 当前脚本中的具体实现方式
3. 两组对比所共用的公共模块
4. 实际仿真输出结果
5. 如何理解当前结果，以及当前代码版本的优缺点

本次说明对应的主要脚本和函数如下。

### 2.1 主对比脚本

1. `space_smooth_music_array_ss_beamspace_compare.m`
   - 用于对比 `旧路线` 和 `新路线(完整T)`

2. `space_smooth_music_array_ss_beamspace_T_compare.m`
   - 用于对比三种波束域投影方式：
     - 完整T
     - 中心截取T
     - 功率选波束T

1. `DOA_three_music_hecheng_fangzhen.m`
   - 对应旧路线
   - 先进入波束域，再在波束域近似做空间平滑并执行 MUSIC

2. `DOA_three_music_array_ss_beamspace.m`
   - 对应新路线
   - 先在阵元域处理协方差矩阵，再投影到波束域执行 MUSIC

1. `mssp.m`

   - 用于从 MUSIC 空间谱中提取局部峰值
   - 输出峰值及其位置，并按峰值大小从大到小排序

## 3. 统一仿真设置

两组对比的基础场景基本一致，核心参数如下。

| 参数 | 含义 | 当前取值 |
|---|---|---:|
| `array_num` | 阵元数 | 64 |
| `fc` | 载频 | 2.7e9 Hz |
| `d` | 阵元间距 | 0.047 m |
| `theta_c` | 双目标中心角 | 13 deg |
| `T` / `Tn` | 快拍数 | 130 |
| `snr` | 信噪比 | 12 dB |
| `Metkl` | Monte Carlo 次数 | 50 |
| `M` | 局部波束分段数 | 32 |
| `M+1` | 局部波束个数 | 33 |
| `B` | 截取或筛选后的波束数 | 25 |
| `search_scale` | 新路线局部搜索宽度放大倍数 | 4 |
| `Q` | 旧路线波束域平滑参数 | 10 |

### 3.1 参考波束宽度

当前脚本中参考波束宽度定义为：

```matlab
bw_64 = 50.8 * 1.45 * lamda / (array_num - 1) / d;
bw_64 = roundn(bw_64, -1);
```

之后构造 10 个双目标角间隔档位：

```matlab
theta_bw = [bw_64/1, bw_64/2, bw_64/3, bw_64/4, bw_64/5, ...
            bw_64/6, bw_64/7, bw_64/8, bw_64/9, bw_64/10];
```

这 10 个档位分别记为：

- `bw/1`
- `bw/2`
- `bw/3`
- `bw/4`
- `bw/5`
- `bw/6`
- `bw/7`
- `bw/8`
- `bw/9`
- `bw/10`

### 3.2 双目标角度构造

对于每一个角间隔档位，两个目标角度定义为：

```matlab
theta_a = theta_c - theta_bw(angle_grid_num) / 2;
theta_b = theta_c + theta_bw(angle_grid_num) / 2;
```

也就是说，每次仿真都以 `theta_c = 13 deg` 为中心，把两个目标对称地放在中心两侧。

### 3.3 快拍数 130 的含义

当前脚本中：

```matlab
T = 130;
t = linspace(0, 1, T);
```

这表示每次 Monte Carlo 实验中，对每个阵元一共生成 130 个离散时间采样点，也可以理解为 130 个快拍。

因此接收数据矩阵的典型维度是：

- 原始阵元域数据：`64 x 130`
- 新路线子阵数据：`59 x 130`
- 波束域数据：`33 x 130`

快拍数越多，协方差矩阵估计通常越稳定；快拍数越少，协方差矩阵更容易受噪声和随机波动影响。

## 4. 公共模块说明

## 4.1 `mssp.m`

当前 `mssp.m` 的处理流程是：

1. 对输入协方差矩阵做前后向平均
2. 取所有长度为 `k` 的重叠子阵
3. 对这些重叠子阵对应的协方差块求平均

对应代码结构为：

```matlab
J = fliplr(eye(M));
crfb = (cr + J * cr.' * J) / 2;

for in = 1:N
    crs = crs + crfb(in:in+k-1, in:in+k-1);
end

ers = crs / N;
```

其中：

- `crfb` 表示前后向平均后的协方差矩阵
- `k` 表示平滑后子阵维数
- `N = M-k+1` 表示可提取的重叠子阵个数

### 4.1.1 一个很重要的实现细节

在当前新路线函数 `DOA_three_music_array_ss_beamspace.m` 中，调用方式是：

```matlab
Rx = mssp(Rxx, subarray_num);
```

而此时：

- `Rxx` 的维度本身就是 `subarray_num x subarray_num`
- 因此 `k = subarray_num`

这会导致：

```matlab
N = M-k+1 = 1
```

也就是说，当前新路线在实现上并没有再对多个重叠子阵做平均，而是退化成：

1. 先做前后向平均
2. 再直接输出整个协方差矩阵

因此，从“严格的阵元域空间平滑”角度看，当前新路线更准确地说是：

`阵元域前后向平均 -> 波束域投影 -> MUSIC`

它保留了“先在阵元域处理，再投影到波束域”的思想，但当前代码版本还没有把阵元域重叠子阵平均这一步完全展开。

这件事在理解结果时非常重要。

## 4.2 `FindLocalPeak_Fun.m`

该函数用于从 MUSIC 空间谱中找局部峰值，核心处理包括：

1. 先取绝对值
2. 与左移、右移后的序列进行比较
3. 判定局部极大值
4. 单独检查两端点
5. 将峰值按大小降序输出

因此后续 DOA 函数中的：

```matlab
[~, peak_ind] = FindLocalPeak_Fun(p_SP);
```

表示先找出全部局部峰，再取最强的前两个峰作为估计结果。

## 5. 第一组对比：旧路线 vs 新路线(完整T)

## 5.1 对比目的

这一组对比的核心目标是：

比较两种不同的算法路线，在双目标相干场景下，哪一种更容易检测出双峰，以及检测成功后的误差表现如何。

对应脚本：

`space_smooth_music_array_ss_beamspace_compare.m`

## 5.2 旧路线的思路

旧路线的基本思路是：

`阵元域接收数据 -> 先做波束形成 -> 得到波束域数据 -> 在波束域近似做空间平滑 -> 波束域 MUSIC`

更具体地说：

1. 根据局部扫描区间构造局部波束形成矩阵 `A`
2. 将阵元域数据 `y` 投影到波束域
3. 在波束域构造协方差矩阵
4. 对波束域协方差矩阵执行 `mssp`
5. 因为平滑后维数变小，所以只取中间连续的 `celln` 个波束
6. 在局部搜索角域内计算 MUSIC 空间谱
7. 取最强的两个局部峰作为 DOA 结果

旧路线的核心函数是：

`DOA_three_music_hecheng_fangzhen.m`

## 5.3 旧路线的具体实现

### 5.3.1 局部波束形成

主脚本中先根据双目标中心角构造局部波束扫描区间：

```matlab
RecvbeamC = (theta_b + theta_a) / 2;
RecvbeamS = RecvbeamC - bw_64 / 2;
RecvbeamE = RecvbeamC + bw_64 / 2;
angle_recv = linspace(RecvbeamS, RecvbeamE, M + 1);
```

这里总共生成 `33` 个局部波束。

之后构造局部波束形成矩阵：

```matlab
A = diag(win_full) * exp(j * 2 * pi * position_full / lamda * sin(angle_recv * pi / 180));
sr_DBF_boshu = A.' * y;
```

因此：

- `y` 是阵元域数据
- `sr_DBF_boshu` 是波束域数据

### 5.3.2 波束域近似空间平滑

在 `DOA_three_music_hecheng_fangzhen.m` 中：

```matlab
Q = 10;
celln = size(Xc, 1) - Q;
Rxxmc = Xc * Xc' / n;
RxxC_mssp = mssp(Rxxmc, celln);
```

由于 `size(Xc,1)=33`，所以：

- `Q = 10`
- `celln = 33 - 10 = 23`

这表示：

1. 先在波束域得到 `33 x 33` 协方差矩阵
2. 再按 `k = 23` 执行 `mssp`

之后为了让导向矢量和降维后的协方差矩阵维数一致，再做一次中心截取：

```matlab
beam_start = floor((size(A, 2) - celln) / 2) + 1;
beam_ind = beam_start : beam_start + celln - 1;
```

也就是只保留中间连续的 23 个波束。

### 5.3.3 MUSIC 搜索范围

旧路线中搜索范围为：

```matlab
angle_search = angle_recv - theta_bw/2 : 0.01 : angle_recv + theta_bw/2;
```

这里的搜索宽度等于当前目标角间隔 `theta_bw`。

这一点和新路线并不完全相同，后面会单独说明。

## 5.4 新路线的思路

新路线的基本思想是：

`阵元域接收数据 -> 先在阵元域处理协方差矩阵 -> 再投影到波束域 -> 波束域 MUSIC`

当前代码版本使用的是：

`阵元域前后向平均 -> 完整局部T投影 -> beamspace MUSIC`

它的出发点是：

1. 阵元域更贴近经典空间平滑理论
2. 协方差矩阵应尽量先在阵元域处理
3. 之后再进入波束域做降维和 MUSIC

新路线的核心函数是：

`DOA_three_music_array_ss_beamspace.m`

## 5.5 新路线的具体实现

### 5.5.1 子阵截取

当前脚本中，新路线并没有使用全部 64 个阵元，而是先取前 59 个阵元：

```matlab
y_sub = y(1:subarray_num, :);
```

其中：

```matlab
subarray_num = 59;
```

因此新路线在当前实现中处理的是 `59 x 130` 的阵元域数据。

### 5.5.2 构造完整局部 T 投影矩阵

```matlab
T_full = diag(win) * exp(j * 2 * pi * position / lamda * sin(angle_recv * pi / 180));
```

其中：

- `T_full` 维度为 `59 x 33`
- 对应 33 个局部候选波束

“完整T”的含义就是：

不再从这 33 个波束里额外裁剪，只保留全部局部候选波束。

### 5.5.3 阵元域处理再投影

在 `DOA_three_music_array_ss_beamspace.m` 中：

```matlab
Rxx = y * y' / n;
Rx = mssp(Rxx, subarray_num);
Rb = T' * Rx * T;
```

这里的处理顺序是：

1. 先在阵元域构造协方差矩阵 `Rxx`
2. 在阵元域对其做 `mssp`
3. 再通过 `T' * Rx * T` 投影到波束域

如前所述，由于这里 `k = subarray_num`，所以当前实现更接近：

`阵元域前后向平均 -> 完整局部T投影 -> MUSIC`

### 5.5.4 MUSIC 搜索范围

新路线中搜索范围为：

```matlab
temp_new = DOA_three_music_array_ss_beamspace( ...
    y_sub, subarray_num, T_full, RecvbeamC, search_scale * theta_bw(angle_grid_num));
```

而：

```matlab
search_scale = 4;
```

因此新路线的实际搜索宽度是：

`4 * theta_bw`

这意味着：

1. 新路线的搜索范围比旧路线更宽
2. 它更容易把两个峰都包含进局部搜索区间
3. 但同时也可能引入更大的搜索区域和更复杂的谱峰结构

这也是当前“旧路线 vs 新路线”对比中必须注意的实现差异之一。

## 5.7 第一组结果解读

### 5.7.1 检测成功率角度

从双峰检测成功率来看：

- 旧路线在 `bw/1` 和 `bw/2` 完全失败
- 新路线在 `bw/1 ~ bw/9` 基本全部成功
- 新路线只在 `bw/10` 开始出现明显退化

因此，如果只看“能不能稳定检出双峰”，当前代码下：

`新路线(完整T)` 明显优于 `旧路线`

### 5.7.2 成功后的误差角度

从成功样本的均方根误差来看：

- 旧路线在 `bw/3 ~ bw/10` 上几乎接近理想状态
- 新路线虽然检出更稳，但误差明显更大

这说明：

1. 旧路线的强项是“在它能分开的区间里，测角精度很高”
2. 新路线的强项是“更不容易塌成单峰”

### 5.7.3 这一组对比的核心结论

第一组对比的核心结论是：

1. 如果以“减少单峰漏检风险”为首要目标，当前更推荐 `新路线(完整T)`
2. 如果只看成功样本里的测角精度，旧路线在 `bw/3 ~ bw/10` 更漂亮
3. 当前旧路线的问题集中在 `bw/1、bw/2`
4. 当前新路线的问题集中在 `bw/10`

## 6. 第二组对比：完整T vs 中心截取T vs 功率选波束T

## 6.1 对比目的

这一组对比是在“新路线”的大框架内部，继续比较不同波束域投影方式的效果差异。

对应脚本：

`space_smooth_music_array_ss_beamspace_T_compare.m`

对比对象是：

1. 完整T
2. 中心截取T
3. 功率选波束T

## 6.2 三种方法的共同框架

这三种方法的共同前提完全相同：

1. 使用同一套双目标相干场景
2. 使用同样的 `59 x 130` 阵元域子阵数据
3. 都先构造 `T_full`
4. 都调用同一个新路线 DOA 函数 `DOA_three_music_array_ss_beamspace`
5. 都使用 `search_scale = 4`

因此，这一组对比的唯一核心差异就是：

`传给 DOA 函数的 T 到底怎么取`

## 6.3 方法一：完整T

完整T的含义是：

直接使用全部局部候选波束。

代码实现为：

```matlab
T_full = diag(win) * exp(j * 2 * pi * position / lamda * sin(angle_recv * pi / 180));
temp_full = DOA_three_music_array_ss_beamspace( ...
    y_sub, subarray_num, T_full, RecvbeamC, search_scale * theta_bw(angle_grid_num));
```

这里：

- `T_full` 的列数是 33
- 不丢掉任何局部候选波束

对应思想是：

尽量保留完整的局部波束域信息，避免因为人为裁剪而丢掉目标相关能量。

## 6.4 方法二：中心截取T

中心截取T的含义是：

从 `T_full` 中只保留中间连续的 `B=25` 个波束。

代码实现为：

```matlab
beam_start = floor((size(T_full, 2) - B) / 2) + 1;
T_center = T_full(:, beam_start:beam_start + B - 1);
```

对应思想是：

假设两个目标主要位于局部波束扇区中心附近，因此保留中间连续的一段波束，就能减少计算量，并避免边缘波束带来的干扰。

但这一路线的风险也很明确：

如果有用的目标信息恰好偏向边缘，那么中心截取就可能把关键波束直接丢掉。

## 6.5 方法三：功率选波束T

功率选波束T的含义是：

先计算各候选波束输出功率，再保留功率最大的 `B=25` 个波束。

代码实现为：

```matlab
beam_pow = sum(abs(T_full' * y_sub).^2, 2);
[~, beam_order] = sort(beam_pow, 'descend');
beam_pick = sort(beam_order(1:B));
T_power = T_full(:, beam_pick);
```

对应思想是：

不是固定保留中间一段，而是根据当前数据自适应地选择“最强”的波束。

这种方法的潜在优点是：

1. 可能更灵活
2. 可能更聚焦于目标主能量所在的波束

但风险是：

1. 强能量不一定等于最有利于双峰分辨
2. 某些有助于分辨的较弱波束可能被直接丢掉
3. 选出的波束不一定连续，会改变局部波束几何结构

## 6.7 第二组结果解读

### 6.7.1 整体成功率排序

从总成功率来看，排序非常清楚：

`完整T > 中心截取T > 功率选波束T`

也就是说，在当前代码实现和当前仿真参数下：

1. 保留全部局部波束信息是最稳的
2. 中心截取会损失一部分有效信息
3. 功率选波束并没有优于完整T，甚至整体更差

### 6.7.2 中心截取T的问题

中心截取T在：

- `bw/8`
- `bw/9`
- `bw/10`

出现明显退化，尤其：

- `bw/9` 只有 `1/50`
- `bw/10` 只有 `2/50`

这说明当双峰结构越来越敏感时，简单地保留中间连续波束，会明显增加漏峰风险。

### 6.7.3 功率选波束T的问题

功率选波束T从 `bw/6` 开始就逐步掉队：

- `bw/6 = 41/50`
- `bw/7 = 23/50`
- `bw/8 = 23/50`
- `bw/9 = 14/50`
- `bw/10 = 18/50`

这说明：

“功率最大”并不等价于“最有利于双峰分辨”。

也就是说，对超分辨 DOA 来说，单纯按能量选波束并不能保证最优。

### 6.7.4 完整T为什么最好

完整T的本质优势在于：

1. 不丢失局部候选波束信息
2. 不依赖额外的中心位置假设
3. 不依赖“高功率波束一定更重要”这一假设
4. 保留了更完整的局部空间结构

因此在当前实现中，它表现出了最好的稳定性。

## 7. 两组对比的综合总结

## 7.1 第一组结论

在 `旧路线 vs 新路线(完整T)` 这组对比中：

1. 新路线(完整T)的双峰检测成功率更高
2. 旧路线在能成功分辨的区间里误差更小
3. 新路线更像是“更稳”，旧路线更像是“成功时更准”

## 7.2 第二组结论

在 `完整T vs 中心截取T vs 功率选波束T` 这组对比中：

1. 完整T明显最好
2. 中心截取T次之
3. 功率选波束T最差

## 7.3 当前更推荐的路线

如果以当前代码版本的结果为依据，推荐顺序是：

1. `新路线 + 完整T`
2. `旧路线`
3. `新路线 + 中心截取T`
4. `新路线 + 功率选波束T`

这里的推荐理由不是“哪个误差最小”，而是综合考虑：

1. 双峰检测是否稳定
2. 是否容易退化成单峰
3. 算法路线是否更接近“先阵元域处理，再投影到波束域”的思路

## 8. 当前代码版本需要特别注意的几点

## 8.1 “新路线”当前仍然不是完全严格的阵元域空间平滑

如前所述，当前 `DOA_three_music_array_ss_beamspace.m` 中：

```matlab
Rx = mssp(Rxx, subarray_num);
```

由于 `k` 等于协方差矩阵维度，所以当前并没有真正利用多个重叠子阵做平均。

因此如果后续要进一步严格化推导和实现，新路线还可以继续改进。

## 8.2 第一组对比还不是完全“同条件”的绝对公平对比

当前第一组对比中，旧路线和新路线还存在以下差异：

1. 旧路线使用 64 阵元的局部波束形成
2. 新路线使用前 59 个阵元构造子阵
3. 旧路线搜索宽度是 `theta_bw`
4. 新路线搜索宽度是 `4 * theta_bw`

因此，当前结果应理解为：

`当前实现版本之间的效果对比`

而不是已经完全消除了所有实现差异后的“纯理论公平对比”。

## 8.3 成功率和均方根误差要一起看

当前表格中的均方根误差是基于成功检测样本统计的。

这意味着：

1. 有些方法虽然均方根误差很小
2. 但它可能在很多样本里根本没有检出双峰

所以不能只看均方根误差，还必须结合成功率一起判断。

## 9. 最终结论

截至当前代码版本，第 7 步的两组对比可以概括为：

1. 在“旧路线 vs 新路线”中，`新路线(完整T)` 的双峰检测稳定性更好
2. 在“新路线内部三种T方案”中，`完整T` 是最优选择
3. 当前最推荐作为后续主线继续分析和扩展的方案是：

`阵元域先处理 -> 完整局部T投影 -> beamspace MUSIC`

同时也要明确：

当前这条新路线虽然已经显示出更好的双峰检测稳定性，但从严格意义上看，仍然存在进一步完善阵元域空间平滑实现的空间。
