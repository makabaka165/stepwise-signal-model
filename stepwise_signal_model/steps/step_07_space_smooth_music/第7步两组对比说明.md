# 第7步新路线说明

## 1. 文档目的

本文档用于总结第 7 步中新路线当前保留的实现，即：

1. `阵元域前处理`
2. `中心截取T波束域投影`
3. `beamspace MUSIC`

文档重点说明以下内容：

1. 新路线的算法思路
2. 当前脚本中的具体实现方式
3. 新路线所共用的公共模块
4. 实际仿真输出结果
5. 如何理解当前结果，以及当前代码版本的优缺点

## 2. 涉及的文件

本次说明对应的主要脚本和函数如下。

### 2.1 主脚本

1. `space_smooth_music_new_route_centerT.m`
   - 用于单独运行 `中心截取T` 版本的新路线

### 2.2 核心 DOA 函数

1. `DOA_three_music_new_route_centerT.m`
   - 对应新路线

## 3. 统一仿真设置

当前新路线使用的基础场景和核心参数如下。

| 参数 | 含义 | 当前取值 |
|---|---|---:|
| `array_num` | 阵元数 | 64 |
| `fc` | 载频 | 2.7e9 Hz |
| `d` | 阵元间距 | 0.047 m |
| `theta_c` | 双目标中心角 | 13 deg |
| `T` / `Tn` | 快拍数 | 130 |
| `snr` | 信噪比 | 12 dB |
| `Metkl` | Monte Carlo 次数 | 50 |
| `M` | 局部波束分段数 | 32 |
| `M+1` | 局部波束个数 | 33 |
| `B` | 中心截取后的波束数 | 25 |
| `search_scale` | 新路线局部搜索宽度放大倍数 | 4 |

### 3.1 参考波束宽度

当前脚本中参考波束宽度定义为：

```matlab
bw_64 = 50.8 * 1.45 * lamda / (array_num - 1) / d;
bw_64 = roundn(bw_64, -1);
```

之后构造 10 个双目标角间隔档位：

```matlab
theta_bw = [bw_64/1, bw_64/2, bw_64/3, bw_64/4, bw_64/5, ...
            bw_64/6, bw_64/7, bw_64/8, bw_64/9, bw_64/10];
```

这 10 个档位分别记为：

- `bw/1`
- `bw/2`
- `bw/3`
- `bw/4`
- `bw/5`
- `bw/6`
- `bw/7`
- `bw/8`
- `bw/9`
- `bw/10`

### 3.2 双目标角度构造

对于每一个角间隔档位，两个目标角度定义为：

```matlab
theta_a = theta_c - theta_bw(angle_grid_num) / 2;
theta_b = theta_c + theta_bw(angle_grid_num) / 2;
```

也就是说，每次仿真都以 `theta_c = 13 deg` 为中心，把两个目标对称地放在中心两侧。

### 3.3 快拍数 130 的含义

当前脚本中：

```matlab
T = 130;
t = linspace(0, 1, T);
```

这表示每次 Monte Carlo 实验中，对每个阵元一共生成 130 个离散时间采样点，也可以理解为 130 个快拍。

因此接收数据矩阵的典型维度是：

- 原始阵元域数据：`64 x 130`
- 新路线子阵数据：`59 x 130`
- 波束域数据：`33 x 130`

快拍数越多，协方差矩阵估计通常越稳定；快拍数越少，协方差矩阵更容易受噪声和随机波动影响。

## 4. 公共模块说明

## 4.1 `mssp.m`

当前 `mssp.m` 的处理流程是：

1. 对输入协方差矩阵做前后向平均
2. 取所有长度为 `k` 的重叠子阵
3. 对这些重叠子阵对应的协方差块求平均

对应代码结构为：

```matlab
J = fliplr(eye(M));
crfb = (cr + J * cr.' * J) / 2;

for in = 1:N
    crs = crs + crfb(in:in+k-1, in:in+k-1);
end

ers = crs / N;
```

其中：

- `crfb` 表示前后向平均后的协方差矩阵
- `k` 表示平滑后子阵维数
- `N = M-k+1` 表示可提取的重叠子阵个数

### 4.1.1 一个很重要的实现细节

在当前新路线函数 `DOA_three_music_new_route_centerT.m` 中，调用方式是：

```matlab
Rx = mssp(Rxx, subarray_num);
```

而此时：

- `Rxx` 的维度本身就是 `subarray_num x subarray_num`
- 因此 `k = subarray_num`

这会导致：

```matlab
N = M-k+1 = 1
```

也就是说，当前新路线在实现上并没有再对多个重叠子阵做平均，而是退化成：

1. 先做前后向平均
2. 再直接输出整个协方差矩阵

因此，从“严格的阵元域空间平滑”角度看，当前新路线更准确地说是：

`阵元域前后向平均 -> 波束域投影 -> MUSIC`

它保留了“先在阵元域处理，再投影到波束域”的思想，但当前代码版本还没有把阵元域重叠子阵平均这一步完全展开。

这件事在理解结果时非常重要。

## 4.2 `FindLocalPeak_Fun.m`

该函数用于从 MUSIC 空间谱中找局部峰值，核心处理包括：

1. 先取绝对值
2. 与左移、右移后的序列进行比较
3. 判定局部极大值
4. 单独检查两端点
5. 将峰值按大小降序输出

因此后续 DOA 函数中的：

```matlab
[~, peak_ind] = FindLocalPeak_Fun(p_SP);
```

表示先找出全部局部峰，再取最强的前两个峰作为估计结果。

## 5. 新路线的思路

新路线的基本思想是：

`阵元域接收数据 -> 先在阵元域处理协方差矩阵 -> 再投影到波束域 -> 波束域 MUSIC`

当前代码版本使用的是：

`阵元域前后向平均 -> 中心截取T投影 -> beamspace MUSIC`

它的出发点是：

1. 阵元域更贴近经典空间平滑理论
2. 协方差矩阵应尽量先在阵元域处理
3. 之后再进入波束域做降维和 MUSIC

新路线的核心函数是：

`DOA_three_music_new_route_centerT.m`

## 5.1 新路线的具体实现

### 5.5.1 子阵截取

当前脚本中，新路线并没有使用全部 64 个阵元，而是先取前 59 个阵元：

```matlab
y_sub = y(1:subarray_num, :);
```

其中：

```matlab
subarray_num = 59;
```

因此新路线在当前实现中处理的是 `59 x 130` 的阵元域数据。

### 5.5.2 构造中心截取T所依赖的完整候选投影矩阵

```matlab
T_full = diag(win) * exp(j * 2 * pi * position / lamda * sin(angle_recv * pi / 180));
```

其中：

- `T_full` 维度为 `59 x 33`
- 对应 33 个局部候选波束

这里先构造完整候选波束投影矩阵，后续实际保留的是其中间连续的一段波束。

### 5.5.3 阵元域处理再投影

在 `DOA_three_music_new_route_centerT.m` 中：

```matlab
Rxx = y * y' / n;
Rx = mssp(Rxx, subarray_num);
Rb = T' * Rx * T;
```

这里的处理顺序是：

1. 先在阵元域构造协方差矩阵 `Rxx`
2. 在阵元域对其做 `mssp`
3. 再通过 `T' * Rx * T` 投影到波束域

如前所述，由于这里 `k = subarray_num`，所以当前实现更接近：

`阵元域前后向平均 -> 中心截取T投影 -> MUSIC`

### 5.5.4 MUSIC 搜索范围

新路线中搜索范围为：

```matlab
temp_new = DOA_three_music_new_route_centerT( ...
    y_sub, subarray_num, T_full, RecvbeamC, search_scale * theta_bw(angle_grid_num));
```

而：

```matlab
search_scale = 4;
```

因此新路线的实际搜索宽度是：

`4 * theta_bw`

这意味着：

1. 新路线的搜索范围比旧路线更宽
2. 它更容易把两个峰都包含进局部搜索区间
3. 但同时也可能引入更大的搜索区域和更复杂的谱峰结构

这也是当前新路线实现中必须注意的一个实现特征。

## 6. 中心截取T实现

## 6.1 中心截取T的共同框架

中心截取T版本的前提是：

1. 使用同一套双目标相干场景
2. 使用同样的 `59 x 130` 阵元域子阵数据
3. 都先构造 `T_full`
4. 都调用同一个新路线 DOA 函数 `DOA_three_music_new_route_centerT`
5. 都使用 `search_scale = 4`

## 6.2 中心截取T

中心截取T的含义是：

从 `T_full` 中只保留中间连续的 `B=25` 个波束。

代码实现为：

```matlab
beam_start = floor((size(T_full, 2) - B) / 2) + 1;
T_center = T_full(:, beam_start:beam_start + B - 1);
```

对应思想是：

假设两个目标主要位于局部波束扇区中心附近，因此保留中间连续的一段波束，就能减少计算量，并避免边缘波束带来的干扰。

但这一路线的风险也很明确：

如果有用的目标信息恰好偏向边缘，那么中心截取就可能把关键波束直接丢掉。

## 7. 综合总结

在当前保留的实现中，中心截取T是新路线实际使用的波束域投影方式。

如果以当前代码版本的结果为依据，可以认为：

1. 新路线在中等角间隔下具备稳定的双峰检测能力
2. 中心截取T实现简单直接，便于继续沿当前代码结构扩展
3. 当角间隔进一步缩小时，当前实现会明显退化，后续仍有改进空间

---

## 8. 当前代码版本需要特别注意的几点

## 8.1 “新路线”当前仍然不是完全严格的阵元域空间平滑

如前所述，当前 `DOA_three_music_new_route_centerT.m` 中：

```matlab
Rx = mssp(Rxx, subarray_num);
```

由于 `k` 等于协方差矩阵维度，所以当前并没有真正利用多个重叠子阵做平均。

因此如果后续要进一步严格化推导和实现，新路线还可以继续改进。

## 8.2 成功率和均方根误差要一起看

当前表格中的均方根误差是基于成功检测样本统计的。

这意味着：

1. 有些方法虽然均方根误差很小
2. 但它可能在很多样本里根本没有检出双峰

所以不能只看均方根误差，还必须结合成功率一起判断。

---

## 9. 最终结论

截至当前代码版本，第 7 步可以概括为：

1. 当前新路线实际采用的是 `中心截取T` 投影方式
2. 当前最推荐作为后续主线继续分析和扩展的方案是：

`阵元域先处理 -> 中心截取T投影 -> beamspace MUSIC`

同时也要明确：

当前这条新路线虽然已经具备可运行的双峰检测流程，但从严格意义上看，仍然存在进一步完善阵元域空间平滑实现的空间。
