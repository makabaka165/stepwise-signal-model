## route 5：common_el_refocus_power

扫描候选俯仰：

```
el_grid = -2:0.25:12
```

对每个 `el0` 做 32 层合成，然后计算聚焦质量，比如：

```
focused_power(el0) = mean(abs(y_combined_el0(:)).^2)
```

或：

```
lambda1(el0) = 最大特征值
```

选择：

e^c=arg⁡max⁡focused_power(el0)\hat e_c = \arg\max focused\_power(el0)e^c=argmaxfocused_power(el0)

然后用 e^c\hat e_ce^c 合成，再跑层次二 rank1。

------

## route 6：common_el_refocus_2dmusic_peak

2D MUSIC 虽然找不到两个峰，但它通常会有一个主峰。这个主峰的 `el` 可能可以作为公共俯仰估计：

```
el_hat = dominant 2D MUSIC peak elevation
```

然后：

```
用 el_hat 重新层合成
→ layer2 rank1 fallback
```

这很适合“同俯仰、方位极近、相干双目标”的情况，因为它们在二维谱上可能就是一个强单峰，但这个单峰的俯仰位置是有用的。

------

## route 7：common_el_refocus_rank1_objective

扫描 `el0`：

```
for el0 in el_grid:
    用 el0 做 32 层合成
    跑 layer2 rank1 covfit
    记录 best objective
选择 objective 最小的 el0
```

这类似 el-bank，但要明确改进：

- 不要只看 DOA 成功；
- 要看 rank1 objective margin；
- 要看 estimated pair 是否稳定；
- 要保证同一 raw observation 公平比较。

这条可能比旧 el_bank 稳。

# 7. 成功标准

在场景 B：

```
el_a = el_b = 0
el_assumed = [0,2,5,10]
```

如果新 route 达到：

```
joint success >= 0.9
```

尤其在：

```
el_assumed >= 5
```

还能成功，那么你就可以说：

> 层次三不一定要做完整 3D/4D covfit；对于同俯仰强相干小间隔，可以先从二维数据估计公共俯仰，再回到成熟的层次二 rank1 fallback。

这会非常漂亮，也很工程化。

如果仍然失败，但 oracle 成功，则说明：

> 公共俯仰估计仍不稳，问题在 el 估计，不在方位 rank1 fallback。

先估公共俯仰再回到层次二是更稳方向，但 el_hat 估计仍需优化。

### 情况 C：refocus route 也失败，但 oracle 成功

写：

二维信息有效，但公共俯仰非 oracle 估计仍不稳定。后续应研究更强 el 估计，而不是扩展 covfit 自由度。

### 情况 D：power/lambda1 估计 el 准，但 rank1 仍失败

写：

el 估计不是瓶颈，可能是合成后 rank1 objective 或 pairing 问题。

### 情况 E：power/lambda1 估计 el 本身不准

写：

公共俯仰估计是主瓶颈，应暂停层次三算法扩展。
