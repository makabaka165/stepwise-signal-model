# 第 8.7 步前四部分路线总结：层次三信息如何补救层次二边界

## 1. 背景与目标

第 8.6 步已经形成层次二工程链路：

```text
65 列动态圆柱工作子阵
    ↓
32 层按 el_assumed 相干合成
    ↓
65×T 一维方位数据
    ↓
真实圆柱流形 MUSIC / rank1 equal-phase covfit fallback
```

该链路在“强相干、同俯仰、小方位间隔、俯仰先验正确”条件下表现很好，但第 8.6 工程压力测试暴露了两个重要边界：

- 当两个目标俯仰差较大时，一维层次二压缩丢失俯仰维信息；
- 当两个目标同俯仰但上游 `el_assumed` 错误时，32 层相干合成方向错误，导致层次二 rank1 fallback 失效。

因此，第 8.7 步的目标不是一开始就建立完整通用 2D az/el 算法，而是验证：

> 65×32 二维圆柱阵信息能否补救层次二的一维压缩边界。

## 2. 第 8.7 第 1 部分：层次三 minimal validation

### 2.1 目标

验证二维信息是否有用，特别是：

- 大俯仰差场景能否由 2D-MUSIC 解决；
- 同俯仰但俯仰先验错误场景中，二维信息是否至少包含可恢复的 oracle 上界。

### 2.2 场景设计

场景 A：目标俯仰差

$$
e_a = 0^\circ,\qquad e_b \in \{0^\circ, 1^\circ, 2^\circ, 5^\circ, 10^\circ\}
$$

场景 B：俯仰先验错误

$$
e_a = e_b = 0^\circ,\qquad e_{\mathrm{assumed}} \in \{0^\circ, 2^\circ, 5^\circ, 10^\circ\}
$$

源模型先固定为理想强相干：

$$
\beta = 1,\qquad \phi = 0^\circ,\qquad \rho = 1
$$

即：

$$
s_2(t) = s_1(t)
$$

### 2.3 Route

- `level2_rank1_fallback_baseline`
- `level2_el_bank_baseline`
- `level3_2d_fbss_music_grid`
- `level3_oracle_el_rank1_covfit_upper_bound`

### 2.4 关键结论

大俯仰差场景：

```text
el_b >= 2°:
level2_rank1_fallback = 0
level3_2d_fbss_music = 1
oracle_el_rank1_covfit = 1
```

说明大俯仰差目标可以由二维信息分辨，层次二一维压缩不适用。

俯仰先验错误场景：

```text
el_assumed >= 5°:
level2_rank1_fallback = 0
level2_el_bank ≈ 0.192
level3_2d_music = 0
oracle_el_rank1_covfit = 1
```

说明同俯仰强相干小方位间隔时，2D-MUSIC 仍可能单峰，但二维信息中存在 oracle 可恢复上界。

## 3. 第 8.7 第 2 部分：二维 rank1 covfit 非 oracle 最小验证

### 3.1 目标

将 `oracle_el_rank1_covfit` 向非 oracle 推进一步。

### 3.2 Route

新增两类非 oracle covfit。

#### 1. common-el rank1 covfit

假设两个目标共享公共俯仰：

$$
e_1 = e_2 = e_c
$$

直接搜索：

$$
(\theta_1,\theta_2,e_c)
$$

模型为：

$$
c_{p,r} =
a_{p,r}(\theta_1,e_c)
+ a_{p,r}(\theta_2,e_c)
$$

$$
R_{\mathrm{model}} =
\alpha G_{\mathrm{FB}}(\theta_1,\theta_2,e_c)
+ \sigma^2 I
$$

#### 2. pair-el local rank1 covfit

用于大俯仰差场景：

- 先用 2D-MUSIC 找两个粗峰；
- 在峰附近局部 refine；
- 构造：

$$
c_{p,r} =
a_{p,r}(\theta_1,e_1)
+ a_{p,r}(\theta_2,e_2)
$$

### 3.3 关键结果

场景 A，大俯仰差：

```text
level3_2d_music = 1
pair_el_local_covfit = 1
oracle = 1
```

说明大俯仰差场景可以由 2D-MUSIC + local covfit refinement 处理。

场景 B，俯仰先验错误：

```text
common_el_covfit ≈ 0.667
oracle = 1
```

说明 common-el 直接 3D covfit 有潜力，但非 oracle 搜索不够稳定。

## 4. 第 8.7 第 3 部分：common-el 2D rank1 covfit 稳定性分析

### 4.1 目标

研究 common-el 直接搜索：

$$
(\theta_1,\theta_2,e_c)
$$

为什么不稳定。

### 4.2 尝试

将参数从：

$$
(\theta_1,\theta_2,e_c)
$$

改为：

$$
(\theta_c,\Delta\theta,e_c)
$$

其中：

$$
\theta_1 = \theta_c - \frac{\Delta\theta}{2}
$$

$$
\theta_2 = \theta_c + \frac{\Delta\theta}{2}
$$

同时分析 objective landscape。

### 4.3 关键结果

在俯仰先验错误场景中：

```text
common_el_old ≈ 0.413
common_el_centersep ≈ 0.387
oracle = 1
non-oracle vs oracle gap ≈ 0.613
```

objective map 显示：

```text
true candidate rank = 186
true-best gap 很小
存在约 99 个竞争低谷
```

### 4.4 结论

common-el 直接 3D covfit 不稳定，不是简单参数化能解决的问题。其 objective landscape 存在很多相近低谷，不适合作为主工程路线继续硬调。

## 5. 第 8.7 第 4 部分：common-el 重聚焦 + 层次二 rank1 fallback

### 5.1 核心思想

不要直接联合搜索：

$$
(\theta_1,\theta_2,e_c)
$$

而是分解成两步：

从二维 65×32 数据中估计公共俯仰：

$$
\hat e_c
$$

用 $\hat e_c$ 重新做 32 层相干合成，然后调用第 8.6 已成熟的层次二 rank1 fallback。

流程为：

```text
65×32 原始数据
    ↓
估计公共俯仰 el_hat
    ↓
用 el_hat 重新做 32 层合成
    ↓
得到 65×T 方位数据
    ↓
layer2 rank1 equal-phase covfit
    ↓
输出 az1, az2
```

### 5.2 Route

#### A. common_el_refocus_power

扫描候选俯仰 $e_0$，计算合成后能量：

$$
P(e_0) =
\frac{1}{QT}
\sum_{q,t}
\left| y_q(e_0,t) \right|^2
$$

选择：

$$
\hat e_c =
\arg\max_{e_0} P(e_0)
$$

然后回到层次二 rank1 fallback。

#### B. common_el_refocus_2dmusic_peak

运行 2D-MUSIC，取其全局最大峰的俯仰位置：

$$
\hat e_c =
\mathrm{el}
\left(
\arg\max_{\mathrm{az},e} P_{2D}(\mathrm{az},e)
\right)
$$

然后回到层次二 rank1 fallback。

#### C. common_el_refocus_rank1_objective

扫描 $e_0$，每个 $e_0$ 下运行层次二 rank1 covfit，选择 objective 最小的 $e_0$：

$$
\hat e_c =
\arg\min_{e_0} J_{\mathrm{rank1}}(e_0)
$$

### 5.3 关键结果

在俯仰先验错误场景 `el_assumed >= 5°` 下：

```text
level2_rank1_wrong_el_assumed = 0
level2_el_bank_old ≈ 0.193
level3_2d_music = 0
common_el_covfit_old ≈ 0.473
common_el_refocus_power = 1.000
common_el_refocus_2dmusic_peak = 1.000
common_el_refocus_rank1_objective ≈ 0.187
oracle_el_rank1_covfit = 1.000
```

同时：

```text
power refocus oracle gap = 0
2D-MUSIC peak refocus oracle gap = 0
rank1-objective refocus oracle gap ≈ 0.813
```

### 5.4 结论

对于同俯仰、强相干、小方位间隔且上游俯仰先验错误的场景，最稳的工程方案不是直接 3D covfit，而是：

> 公共俯仰重聚焦 + 层次二 rank1 fallback

其中：

- power refocus 可作为主方案；
- 2D-MUSIC peak refocus 可作为备选；
- rank1 objective refocus 不建议使用。

## 6. 第 8.7 当前总体结论

第 8.7 并不是一个单一 2D-MUSIC 算法，而是把层次二边界拆成了两类场景。

### 场景 A：大俯仰差

当两个目标俯仰差较大时：

```text
2D-MUSIC / pair-el local covfit
```

即可解决。此时目标在二维角域中已经有明显俯仰分离，不再是纯一维方位超分辨问题。

### 场景 B：同俯仰但俯仰先验错误

当两个目标共享公共俯仰，但层次二使用的 `el_assumed` 错误时：

```text
common-el refocus + layer2 rank1 fallback
```

最有效。

### 工程分流

因此，第 8.7 当前工程路线应写成：

```text
如果 2D-MUSIC 能形成两个二维峰：
    使用 2D-MUSIC 或 pair-el local covfit

如果 2D-MUSIC 单峰，但存在清晰公共俯仰：
    使用 common-el refocus
    然后回到 layer2 rank1 fallback

如果公共俯仰不清晰，或目标幅相/强弱结构复杂：
    输出低置信度或留作未来 general model
```

## 7. 当前适用范围和限制

### 适用范围

- 强相干；
- 近等幅；
- 近同相；
- 方位小间隔；
- 大俯仰差时可用 2D-MUSIC；
- 同俯仰但俯仰先验错误时可用 refocus + layer2 fallback。

### 仍未覆盖

- 幅度差很大；
- 近反相；
- 任意 $\rho$；
- 多目标；
- 多散射点；
- general $R_s$ 模型；
- 完整 4D 全局 az/el pair covfit。
