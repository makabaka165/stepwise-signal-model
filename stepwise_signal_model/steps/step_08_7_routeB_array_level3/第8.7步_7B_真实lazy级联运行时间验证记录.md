## 执行结构说明

本轮实现了真实 lazy execution：若前序 gate 已经选定 route，后续未触发 route 的函数不调用，并在 trial CSV 中记录 executed_level2_music、executed_refocus、executed_level2_rank1、executed_2dmusic、executed_pair_local。

为保持与第 7 部分一致，本脚本保留 common-el refocus 作为 level2/rank1 低成本早停的安全门控。因此 level2 MUSIC route 本身先计算，但其早停确认会在 refocus 诊断后进行；这避免大俯仰差场景被过早误分流到层次二。

## 补充观察

- 与 full-route observable dispatch 的逐 trial route agreement 为 0.716；主要差异来自 common-el 场景中 full dispatch 倾向选择 `common_el_refocus_power_rank1`，而 lazy gate 在部分样本中早停到 `level2_rank1_fallback`。二者成功率几乎一致，但 route 名称不完全一致。
- 最耗时场景集中在 large-el 组，尤其 `F_el10_beta05_phase180_rho07` 和 `E_el5_beta1_phase0_rho07`。这些场景必须执行 2D MUSIC 与 pair-local，因此 lazy runtime 接近 full-route baseline。
- rho/beta/phase 的 common-el 组有明显 runtime reduction，原因是多数样本在 refocus/rank1/low-confidence 前已停止，不再触发 2D MUSIC 与 pair-local。
