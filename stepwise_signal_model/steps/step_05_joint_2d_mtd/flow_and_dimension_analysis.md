# Step 05 当前版本流程与维度说明

当前第 5 步已经切换为“仿真阶段局部单目标链路”，不再走之前那个全 `3201` 联合波束的工程化全域扫描。

当前思路是：

1. 仍然先按当前扇区中心选择工作子阵。
2. 在当前工作子阵上，生成方位轴和俯仰轴的一维波束中心。
3. 用“离 `cfg.tgt.az` / `cfg.tgt.el` 最近的波束中心”选出当前局部中心波束。
4. 围绕这个中心，构造 5 个唯一波束：
   - 方位三波束：`(azLeft, elCenter)`、`(azCenter, elCenter)`、`(azRight, elCenter)`
   - 俯仰三波束：`(azCenter, elDown)`、`(azCenter, elCenter)`、`(azCenter, elUp)`
   - 其中中心波束共享，所以一共是 5 个唯一波束，而不是 6 个
5. 对这 5 个局部波束统一做波束形成和 MTD。
6. CFAR 只放在中心波束的 RD 图上。
7. 中心波束 CFAR 检出多个检测单元后，先做局部峰值筛选和 RD 二维聚类。
8. 最终三波束比幅测角只对“提取后的最强目标代表点”做。

## 1. 记号

- `N`：当前工作子阵的有效阵元数
- `R`：距离单元数
- `P`：脉冲数
- `D`：多普勒单元数
- `B_local`：当前局部唯一波束数，这里固定为 `5`

在当前默认配置下：

- `Naz = 192`
- `Nel = 32`
- `sectorHalf = 60 deg`
- `subNaz = 2 * floor(60 / 1.875) + 1 = 65`
- `N = 65 * 32 = 2080`
- `R = 3000`
- `P = 32`
- `D = 32`

所以本版本第 5 步最核心的维度链路就是：

- `pcCube = 2080 x 3000 x 32`
- `beamCube = 5 x 3000 x 32`
- `rdCube = 5 x 3000 x 32`
- `center beam CFAR input = 1 x 3000 x 32`

## 2. 每一步输入输出维度

### 2.1 阵元级脉压结果

输入到第 5 步主函数的是：

- `pcCube(element, range, pulse)`
- 维度是 `N x R x P = 2080 x 3000 x 32`

含义：

- 第 1 维 `2080`：工作子阵的阵元编号
- 第 2 维 `3000`：距离单元
- 第 3 维 `32`：脉冲编号

这一步还没有形成波束。

### 2.2 单个波束先得到 `R x 32`

对任意一个候选波束，设其接收权向量是：

- `w : N x 1`

固定某个脉冲时：

- `pcCube(:, :, p) : N x R`
- `w^H : 1 x N`

左乘之后得到：

- `w^H * pcCube(:, :, p) : 1 x R`

对全部 `32` 个脉冲都做完并堆起来，就是：

- `beamMat : R x P = 3000 x 32`

这正对应导师提到的：

- “一个波束先得到 `R x 32`”

### 2.3 五个局部唯一波束得到 `5 x R x 32`

当前版本不是构造全二维联合波束网格，而是只构造 5 个局部唯一波束：

- `azLeft`
- `center`
- `azRight`
- `elDown`
- `elUp`

所以波束形成之后得到：

- `beamCube(localBeam, range, pulse)`
- 维度是 `5 x 3000 x 32`

这是当前版本最重要的降复杂度来源。

### 2.4 三波束组的视角

虽然总共只形成了 5 个唯一波束，但为了后续三波束测角，可以把它看成两个局部三波束组：

- 方位组：`[azLeft, center, azRight]`
- 俯仰组：`[elDown, center, elUp]`

所以从 `beamCube(5, R, P)` 中可以直接抽出：

- `azGroup = 3 x R x P`
- `elGroup = 3 x R x P`

注意这里并没有重复形成中心波束，只是索引复用。

### 2.5 MTD 之后变成 `5 x R x D`

对 `beamCube(5, R, P)` 沿脉冲维做 MTD：

- 输入：`5 x 3000 x 32`
- 输出：`rdCube(localBeam, range, doppler)`
- 维度：`5 x 3000 x 32`

数值上第三维仍然是 `32`，但物理含义已经从脉冲维 `P` 变成了多普勒维 `D`。

同样，也可以从中抽出：

- `azGroup.rdCube = 3 x 3000 x 32`
- `elGroup.rdCube = 3 x 3000 x 32`

## 3. CFAR 放在什么位置

当前版本明确采用：

- 先做局部五波束波束形成
- 再做 MTD
- 然后只对中心波束 RD 图做 CFAR

也就是：

- CFAR 输入不是 `5 x R x D`
- 而是中心波束切片 `1 x R x D`

在代码里，中心波束就是局部波束编号 `2`。

所以 CFAR 实际检测的是：

- 中心波束对应 RD 图上的检测单元

输出不是目标列表，而是检测单元列表：

- `rangeIdx`
- `dopplerIdx`
- `metric`
- 以及映射后的 `range`、`velocity`

如果中心波束 CFAR 检出了多个点，当前版本会同时保留三层结果：

- 原始 CFAR 检测点
- 局部峰值筛选后的点
- 聚类得到的目标代表点

## 4. 当前最终输出是什么

当前版本不是多目标聚类接口，而是“局部单目标链路接口”。

主要输出分成三部分：

### 4.1 波束选择结果

- 当前工作子阵规模
- 方位波束轴 / 俯仰波束轴
- 选中的中心波束
- 方位三波束
- 俯仰三波束

### 4.2 中心波束检测结果

输出中心波束上的三层检测/提取结果：

- `jointOut.cfarRaw`
- `jointOut.peakDetections`
- `jointOut.targets`

其中每一层都会给出对应的：

- `count`
- `rangeIdx`
- `dopplerIdx`
- `range`
- `velocity`
- `metric`

### 4.3 最强检测点的三波束比幅测角结果

如果中心波束 CFAR 检出了多个点，当前版本先做目标提取，再从目标代表点里取最强的一个：

- `(rangeIdx_best, dopplerIdx_best)` for strongest extracted target

然后只在这个单元上读取：

- 方位三波束的复响应
- 俯仰三波束的复响应

再做三波束比幅测角。

因此最终精测角输出只有一个：

- `bestAz`
- `bestEl`
- `bestRange`
- `bestVel`

## 5. 三波束比幅测角在当前版本中的位置

当前版本里，三波束比幅测角不是用来“找目标”的，而是用来“精化角度”的。

顺序是：

1. 中心波束 CFAR 先找到检测单元
2. 对检测单元做局部峰值筛选和 RD 二维聚类
3. 从目标代表点里取最强的一个
4. 在这个检测单元上读取局部三波束响应
5. 用左右差和比

   `rho = (A_right - A_left) / (A_right + A_left + eps)`

   做角度反演

所以它回答的是：

- “这个已经检测到的点，它的精细角度是多少”

而不是：

- “全扇区里有哪些目标”

## 6. 当前版本与之前工程版思路的区别

之前工程版思路是：

- 全二维联合波束全域扫描
- 全域 MTD
- 全域 CFAR
- 检测后再做目标提取和聚类

当前版本不是这条路，而是：

- 已经假定当前扫描到了目标附近
- 只取目标附近的局部 5 波束
- 只在中心波束上做 CFAR
- 只在中心波束 RD 平面内做局部峰值和聚类
- 只对最强目标代表点做三波束精测角

所以当前版本的定位是：

- 仿真阶段
- 单目标局部验证链路
- 重点验证“局部三波束 + MTD + 中心波束 CFAR + 比幅测角”是否跑通

而不是：

- 完整工程版多目标搜索检测链路

## 7. 当前版本最核心的维度总结

一句话总结当前版本的维度：

- `pcCube = N x R x P = 2080 x 3000 x 32`
- 单个波束输出 `R x P = 3000 x 32`
- 五个局部唯一波束输出 `5 x R x P = 5 x 3000 x 32`
- MTD 后得到 `5 x R x D = 5 x 3000 x 32`
- 中心波束 CFAR 输入是 `1 x R x D = 1 x 3000 x 32`
- 方位精测角读取 `3 x 1` 响应
- 俯仰精测角读取 `3 x 1` 响应

这就是当前代码真正对应的处理链路和维度含义。
